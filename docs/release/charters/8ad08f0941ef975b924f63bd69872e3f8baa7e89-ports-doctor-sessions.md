## Findings

**PD-01 (S4, wording).** For a pane whose `ports` reply has `status: "unsupported"` on a server that has the method, `summon ports` and `summon doctor` say `live ports incomplete for theta (1 terminal pane does not support live ports)`, but `summon inspect theta` says `live ports: this Rex server has no live ports (needs API 16 or later)`, which blames the server version. Repro: fake `rex` answers `block call ... ports` with `{"status":"unsupported","ports":[]}` for the root block; run `ports`, then `inspect theta`. Both exit 0. Source of the inspect text: `parsePortsReply` returns `PORTS_UNSUPPORTED` for an `unsupported` reply (`src/backends/rex/ports-reply.ts`).

**PD-02 (S4, wording).** When the live read is incomplete, `summon ports` prints `No port conflicts` (with the sym.ok glyph) directly above `note: live ports incomplete for theta (timed out)` (also with the old-server note). The check mark covers only the static claims; in the repro a held conflict on 3000 exists but was not read. Repro: held conflict on 3000, fake `portsDelayMs: 15000`; run `ports` (exit 0, 4112 ms). The note does explain the gap, so the reader has a workaround.

**PD-03 (S4, documentation).** `summon ports` and `summon doctor` reconcile an ended Rex workspace (they rewrite `status/<project>.json` and remove the launch manifest), but docs/rex.md lists only `summon status`, `summon open`, `summon briefing` and the monitor as reconciling reads, and its Live ports section says "Nothing is saved". Repro: launch `theta`, remove its session from the fake server, run `ports`: inventory diff shows `status/theta.json` changed and `theta.launches/<id>.json` removed. The same readAllStatuses path existed in v2.1.1 `src/ports.ts`, so this is not a 2.2.0 regression, and the write is the correct reconciliation.

**PD-04 (S4, outside normal use).** `summon session add t2 edge` refuses a symlinked session file (`summon: error: Refusing to replace a session symlink: t2`, exit 1, target unchanged, no staging file), but `summon session list` lists `t2` and `summon session show t2` prints the symlink target's content (`precious`). No boundary is crossed (planting the link needs the user's own access, and a launch accepts only registered names), but the policy is asymmetric.

Observations that are not findings: `inspect` took about 4.2 s against a fake `rex` that ignores its own `--timeout 2s` (Summon passes `--timeout 2s` and kills at 2 s plus a 2 s grace; it stopped after the first silent pane as documented). With parent-only SIGINT, the slow fake `rex` children ran to completion; with a real `rex` they end at their own 2 s timeout, and a process-group SIGINT kills them. `ports` exits 1 with a raw `ENOTDIR` when `status/` is a regular file (corrupt install, doctor reports it). `doctor` names `Could not inspect lock directory .../status: EACCES` (and `ENOTDIR`), still reports a stale `config.lock` in the other directory, reports `Could not check port conflicts` as a FAIL instead of crashing, and exits 2. `briefing` shows `Commit history unavailable` and `Working tree status unavailable` for non-Git directories, a broken `.git` file and a deleted directory, counts `2 known overnight commits`, and exits 0.
